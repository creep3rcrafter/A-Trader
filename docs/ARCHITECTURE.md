# A-Trader Architecture

**Reviewed:** 2026-10-10

## Starting repository

The repository is a fresh Flutter application (`a_trade`) on Flutter 3.44.2 / Dart 3.12.2. It contained only `lib/main.dart` with a counter demo, a matching `test/widget_test.dart`, the standard Flutter lint configuration, and no API, database, router, state-management, or backend packages. Git status reported no VCS roots in the IDE. Phase 1 therefore does not migrate an existing architecture.

## Phase 1 architecture

- **Presentation:** Flutter Material widgets; responsive dashboard using available width rather than a separate web/desktop implementation. Small screens use a single column; wide screens can use a constrained content grid. Current daily charts are inline on each card as described below.
- **State:** local widget/app state for the theme, settings, current ideas, and saved statuses. Built-in Flutter `StatefulWidget` state avoids adding a package before complexity requires one.
- **Data:** in-code fixtures explicitly named and presented as mock. There are no HTTP clients, secrets, persistence, or claims of provider connectivity.
- **Navigation:** a small dashboard/saved/history view selector plus a settings screen/dialog; preserve the current page across theme changes.
- **Tests:** widget tests use Flutter's test binding; no external API, clock, or network dependency.

Historical candles are not predictions; forecast overlays and intraday data remain deferred.

See `DATA_PROVIDER_RESEARCH.md` for the Basic non-display restriction. Watchlist use remains personal research/testing only, not a promise of shared production display rights.
- **Domain contract:** `lib/market_data/market_data.dart` defines provider/feed identity, source and retrieval timestamps, quote/bar fields, corporate-action adjustment metadata, and a repository interface independent of any one vendor.
- **Normalization:** the Alpaca normalizer maps the documented IEX trade, quote, and daily-bar response shapes into that contract, merges quote/trade timestamps without discarding provenance, and rejects malformed or internally inconsistent data.
- **Freshness:** quote freshness is derived from the source timestamp and caller-supplied maximum age. Delayed feeds are always marked delayed; stale and future-dated data are not treated as current.
- **Network/security:** `backend/bin/market_data_server.dart` defaults to loopback with server-side Alpaca IEX and Twelve Data adapters. Explicit LAN mode adds authenticated static hosting and APIs as described below. It reads credentials from server environment variables, requires explicit data-terms confirmation, forces the selected free feed, enforces quotas, and only enables Alpaca memory caching when separately permitted. No provider credential or direct third-party request is embedded in Flutter. Ideas automatically loads read-only quotes and bounded daily histories for ten stocks through this service, one card at a time; there is no polling or paid fallback.
- **Local service boundary:** read-only JSON endpoints expose normalized `/api/v1/market-data/quote` and `/api/v1/market-data/bars` results plus `/health`. Development browser requests require a single exact configured origin. LAN requests additionally require session authentication and trusted Host/Origin validation. Provider errors are sanitized and no paid fallback is attempted.
- **Coverage:** Alpaca Basic IEX is a single-venue source for supported US stocks/ETFs, not consolidated market data, and its standard individual plan does not provide OTC data. Unsupported and absent symbols remain unavailable; they are not replaced by fabricated or paid data.
- **Provider setup UI:** Settings accepts loopback (or the web app's same origin) and checks `/health` immediately and every 30 seconds while open, without overlapping requests. An accessible neutral checking circle becomes a green checkmark or red X with error details. Closing Settings cancels polling; URL edits invalidate stale results. It never accepts or stores provider secrets. The backend reports booleans for configured credential presence, enabled state, and implementation status, without returning values. These are readiness indicators only—not provider authentication or entitlement checks. Health polling does not request market data or model analysis.
- **Windows-only process ownership:** `backend_process.dart` conditionally imports a web stub or native controller; native availability uses the real Windows OS, never Flutter's target-platform styling override. Only native Windows renders explicit Start/Stop buttons. The app-lifetime controller locates a source checkout and launches the fixed `desktop_backend.ps1` without shell text or HTTP process-control routes. Start rechecks reachability and only targets HTTP loopback port 8765. The supervisor imports existing private settings, forces IPv4 loopback/8765 with auth off and no static root, and invokes the Dart VM directly. Stop signals a random per-instance Windows kernel event; the supervisor kills only its retained child handle. It monitors the owning app handle for abrupt-exit cleanup. External backends are observed but never killed; there is no port/name-based termination. Source, restored backend packages, SDK and existing script policy are required; a standalone installed executable is not a bundled backend distribution. See `LOCAL_PROVIDER_SETUP.md`.
- **Research presentation:** `lib/market_data/local_market_data_service.dart` uses browser-compatible `package:http` only; it never imports the `dart:io` provider adapters. Inject `LocalMarketDataService` into `MyApp` for tests. The app closes only services it creates, and the service closes only its owned client. A shared loopback validator and disabled redirects prevent remote local-service requests.
- **Ideas navigation:** `live_ideas_view.dart` replaces mock recommendations and the manual Market data tab with ten explicitly unscreened temporary stocks. Latest-available quotes and inline daily histories load once, one complete card at a time; Refresh explicitly reloads all ten. Prices, source timestamps, current freshness, provider/feed and expandable bid/ask/coverage details come from validated backend responses. Company names are static watchlist labels, not a provider identity lookup. No entry/stop/risk/GPT claims are fabricated. Saved filters the same session-only list without re-fetching; History is empty until journaling exists.
- **Quota behavior:** One parent-owned sequential queue completes quote then history per ticker. The first quote is immediate; once identified, Schwab requests are at least seven seconds apart (20 requests span at least 133 seconds, below ten/minute), and Twelve Data requests at least eleven seconds apart (below seven/minute). Unknown-provider requests conservatively use eleven seconds. Alpaca retains unpaced sequential loading: its adapter has a shared 180-request/minute safeguard, bounded pagination and provider-header cooldown handling. Last request time/spacing survive refresh generations; stale callbacks and waits cannot issue more requests after service/URL changes or disposal. The backend remains the authoritative shared quota gate, including other clients/manual tools. Quota/configuration/transport failures stop the queue and mark remaining cards not requested; history failures preserve valid quotes. A ticker 404 permits history/other cards to continue. No market-data polling, automatic retries or provider fallback occurs. Settings-only health polling is independent.
- **Response/lifecycle safety:** Normalized responses are strictly checked for expected enums, matching symbols/source identities, finite consistent prices, integer volumes, timestamps with explicit offsets, date/timezone semantics and required metadata. Arbitrary backend error/coverage text is not rendered: errors use safe local messages and coverage labels derive from validated provider identity. Request generations discard old results after refresh, saved backend URL/service changes and disposal. Navigating tabs or opening Settings retains loaded quotes without extra requests. Health checks discard results after URL edits. Every market request uses the saved in-memory Settings URL; Save is required to apply changes.
- **Local launch:** `scripts/start_web.ps1` and the IDE Flutter configuration use `localhost:3000`; `scripts/start_backend.ps1` sets the exact matching CORS origin and backend port `8765`. Both processes must restart after port/origin changes; credentials and terms flags remain in the backend process environment.
- **Verification boundary:** HTTP fixtures and widget tests validate the client/presentation without using credentials or calling a live market provider. Successful builds/tests do not verify account authentication, entitlement, symbol coverage or data-use rights.

## Local AI and same-origin web client

- **Persistent configuration:** `setup_local.ps1` uses secure prompts and current-user Windows DPAPI to store private configuration in ignored `.local` files. Launch scripts decrypt only an allowlisted set of server variables, preserving explicit environment overrides. Secrets never enter Flutter build flags, source, browser storage or health responses. DPAPI binds credentials to the Windows user/machine; it is not a portable backup or protection against same-user malware.
- **LAN server:** `start_lan.ps1 -AcknowledgePrivateNetworkOnly` builds Flutter and serves static assets plus APIs on port 3000. Password login, throttling, eight-hour expiring `HttpOnly; SameSite=Strict` cookies, bounded input, traversal-safe static paths and trusted Host/Origin checks protect access. LAN provider display rights are independent default-deny gates. HTTP is unencrypted: trusted-private LAN only, no router forwarding, no automatic firewall changes. HTTPS/VPN is required for untrusted networks.
- **Model routing:** Backend clients use OpenAI Responses when an OpenAI key is configured, otherwise loopback LM Studio chat completions with `google/gemma-4-e4b` by default. There is no silent fallback on provider errors. Explicit assistant enablement, model-forwarding rights and LM Studio local-only confirmation are required. LM Link/remote routing must be disabled; localhost/model visibility alone does not establish local inference. Optional LM Studio authentication tokens remain private. Health labels configuration, not verified availability.
- **Bounded requests:** Assistant calls fetch verified quote context server-side, bound prompt/output sizes, cap concurrent and total process calls, enforce timeouts and sanitize failures. Responses include provider/model, provenance and limited input/usage audit metadata. Durable cost accounting, token-price estimation, full prompt/input journaling and version history remain unimplemented.
- **Frontend boundary:** LAN builds use `--dart-define=A_TRADER_SAME_ORIGIN=true` so all data/model/health requests go to the web page's own origin. Development builds retain `127.0.0.1:8765`. URL validation permits loopback or exactly the current browser scheme/host/port, not arbitrary LAN or remote backends. Native applications remain loopback-only in this increment.
- **Explicit analysis:** Ask AI appears on cards with verified quotes and sends only the symbol and saved editable prompt to the backend. There are no automatic model requests on load, refresh, settings edits or navigation. Responses identify the actual provider/model and remain explanations, not evaluated recommendations or trade plans. Changing the prompt or backend discards old in-flight explanations.
- **Presentation safety:** The assistant client validates nonempty bounded explanation text and known provider identity, displays sanitized failures, never accepts API credentials, and owns/closes only HTTP clients it created. A session-expiry response asks the user to reload and sign in. Model explanation text is rendered as text, not executable HTML.
- **Model limitations:** Quote-only context cannot establish catalysts, fundamental quality, microcap eligibility or liquidity history. Numeric entry/stop/allocation decisions remain unimplemented rather than delegated to the model. Full screening, journaling, prompt-version persistence and measurable performance remain later phases.

## Tool-first local research

The user-triggered **Research with local tools** action requests research for one selected ticker, a seven-calendar-day lookback and the configured holding horizon. Unlike quote-only Ask AI, this route permits bounded LM Studio function requests to read-only quote/history/SEC metadata tools. The server validates and executes tools; the model cannot run shell commands, browse arbitrary URLs, trade, or retrieve credentials. Tool output is untrusted evidence, not executable instructions.

The frontend renders actual tool names, source URLs, source dates and retrieval times separately from generated text. It rejects unknown tools, malformed metadata and unsafe source URL schemes. Sources are evidence, not a verified probability of profitable trading. Optional personal DuckDuckGo snippets are described below; arbitrary browsing, article ingestion and social collection remain unavailable. The fixed temporary watchlist is not yet replaced by broad discovery or ranked recommendations.

### Bounded research implementation (2026-10-12)

- `POST /api/v1/assistant/research` preserves the existing Flutter contract: `symbol`, `prompt`, integer `holdingDays` (1-365) and `lookbackDays` (1-30); returns `explanation`, `provider:"lmstudio"`, `model`, `sources`, `toolsUsed`, `limitations` and bounded usage counters.
- Research explicitly constructs an LM Studio client **even when OpenAI is configured**. Ask AI retains its existing routing; neither path switches providers on errors. Both share one process call/concurrency budget. Each research chat POST consumes a call after local-model metadata preflight, including failed POST attempts; listing models is not a generation call.
- `backend/lib/research.dart` dispatches only `get_market_quote`, `get_daily_bars`, `get_sec_filings`, `get_technical_indicators` and, with explicit personal-search permission, `search_public_web`. Arguments contain exactly the requested normalized symbol. Tools cannot select URLs, queries, credentials, shell commands, providers, date windows or orders. Every batch is validated before executing any member; IDs are unique and bounded.
- At most three chat turns and four tool executions per action. Assistant tool messages are replayed with their native `tool_calls`; each actual JSON result is sent as `role:"tool"` with the original `tool_call_id`. The last turn (or exhausted tool budget) uses `tool_choice:"none"`; further calls fail explicitly.
- Quote/bar tools reuse the selected gated adapter and its quotas, without extra providers or paid feeds. History covers at most 30 completed calendar days, excludes today's incomplete bar, requests raw adjustment and rejects mismatched symbols/feeds, out-of-window, unordered/duplicate or oversized results. Returned sessions are not evidence of complete coverage or microcap eligibility.
- SEC metadata requires `A_TRADER_SEC_TERMS_CONFIRMED=true` and `SEC_USER_AGENT` with an application identity and real contact email. Only fixed SEC ticker-map and submissions JSON endpoints are permitted; safe archive URLs are constructed from validated CIK/accession/document metadata. Requests sharing one HTTP client serialize acquisition, recheck actual send times, stay one second apart and reserve at most ten per rolling minute. 403/429 blocks further requests for at least a minute, honoring longer valid `Retry-After`; no retries or rotation. No filing-document download, company facts, news or social ingestion is included.
- Sources and timestamps are assembled by deterministic handlers, not model output; repeated URLs are deduplicated. Unsupported/unsafe links in generated explanation cause a sanitized error. Flutter restricts market/SEC sources to known provider paths and the requested ticker. Web sources additionally require the narrow `kind:"webSearch", provider:"duckduckgo"` provenance, a recorded search tool execution, a safe public HTTPS hostname and no publication date. This guards provenance, not the truth of every sentence; local model interpretations remain unverified and cannot supply quantitative calculations or trade decisions.
- Missing tool data/permission is an explicit `unavailable` result with no sources and a limitation sent to the model and UI. Local model failure is an explicit request failure. A model answering without native calls returns empty evidence and a visible unverified-tool-capability limitation, never a successful-tool claim.

Fixture tests and the opt-in native smoke test are separate. The native test uses a clearly labelled synthetic ticker/price repository, never live market credentials or SEC requests; it checks native tool request, validated execution, delivery of the linked result and final reproduction of the fixture value. See setup instructions and the checklist for actual verification status.

### Optional limited personal DuckDuckGo search (2026-11-05)

The [LM Studio plugin](https://www.lmstudio.ai/jms/duck-duck-go-search) uses `uvx duckduckgo-mcp-server`. A-Trader uses the same underlying **0.7.0** package, pinned by wheel URL/SHA-256 in `scripts\ddg_requirements.txt`, through its own search-only stdio adapter. Do not connect the unrestricted plugin to this research flow: its autonomous loop cannot enforce A-Trader's actual three-turn/four-tool budget, and its upstream server also exposes page fetching.

`backend\lib\web_search.dart` starts only the fixed project-local Python/adapter paths with isolated Python, no shell and no inherited credentials/proxy/provider configuration. MCP initialize/list/call validates the single `search` schema, protocol/server identity, reply IDs and result shape; output is capped at 64 KiB with a 20-second exchange deadline and subprocess cleanup. Nothing is installed or downloaded during requests. Missing permissions/runtime produce explicit unavailable results. `/health` reports runtime presence, unverified availability, limits and a latched stopped state, not entitlement or live connectivity.

The fixed outbound query is `<requested symbol> company news earnings`, with at most three results. Neither the saved prompt, model-generated text, provider data nor credentials become queries. Shared backend limits are one attempt per 60 seconds, one in flight and ten attempts per server process, with no scheduled retries or alternate search provider. Every requested tool execution (including unavailable results) still consumes the original four-tool budget.

Inspection of upstream 0.7.0 found `auto` search fallback, Chrome headers and an internal 429 retry even for `httpx`. The adapter uses the inspected package's search-result parser but **replaces `_request`**: `httpx` only, identifying application User-Agent, verified TLS, no environment proxy, no redirect, no retry, 12-second HTTP timeout, 15-second search deadline and 512 KiB decompressed response cap. Non-200, CAPTCHA/challenge, empty, malformed and transport-error outcomes stop search for that server process. Browser impersonation, optional browser extras, block/CAPTCHA bypass, `fetch_content` and `expand_link` are never served/called. A restart is not permission to evade a provider block; leave disabled until normal access is permitted.

Only bounded untrusted titles/snippets and source links are returned. Backend validation unwraps DDG result redirects without requesting them, permits HTTPS/443 without credentials/fragments, rejects local/private/literal-IP/reserved hosts, and resolves DNS to reject non-public addresses. No linked page is downloaded, redirected or verified. Retrieval time is backend time **after** the search; publication dates stay null. Frontend link checks are lexical (browser DNS is not a second validation), and link destination ownership can change. Quote and indicator tools remain numeric authority; snippet claims and model interpretations are not verified facts. No all-relevant-data, scoring, performance or redistribution-rights promise is made.

## Deterministic daily-indicator foundation

The indicator engine is a pure Dart domain calculation layer over existing `MarketBar` values, separate from provider access, model interpretation and widget state. The foundation supplies session colors/counts/fractions, green:red ratio, close-to-close lookback returns, SMA and relative volume; the follow-on slice adds SMA trend, EMA and RSI. No new provider or dependency is introduced. The card action and bounded research tool expose these deterministic calculations without giving the model quantitative decision authority.

`lib/market_data/daily_indicators.dart` exposes `DailyIndicatorConfig`, `DailyIndicatorInputValidator` and `DailyIndicatorEngine.calculate(config: ..., bars: ...)`. Results are immutable and serializable. Each metric records availability/reason, formula/version/parameters, units, required/observed samples, stale count, window dates, retrieval times and missing dates. Overall provenance preserves the input symbol/provider/feed/adjustment, cutoffs, volume/date semantics and per-bar source/retrieval timestamps. Return values are fractions (`0.05` means 5%); relative volume and green:red are ratios; SMA retains price units.

The follow-on formula version is `daily-indicators-v2`. `trendLag` defaults to one session, `rsiPeriod` to 14; both are bounded positive session counts. `smaTrend` reports `{slope, direction}` with fractional normalized SMA slope and rising/falling/flat direction. EMA seeds from the first N-close SMA and processes the complete supplied expected history; RSI seeds the first P gain/loss delta means and applies Wilder smoothing over that history. Missing or stale seeded history blocks recursive values rather than silently resetting their seed. RSI conventions are flat=50, positive gain/zero loss=100, positive loss/zero gain=0. Warmup/seed parameters, required counts and actual history range are preserved in each metric.

Raw SMA, SMA trend, EMA and RSI remain arithmetic summaries of the supplied prices, with an explicit unverified-corporate-action distortion caveat; they are not economic returns or trade signals. Only `closeReturn` retains the default-deny raw comparability gate. No integration silently confirms that flag.

Callers must supply explicit analysis and completed-session cutoffs, window sizes, maximum retrieval age and, to establish complete coverage, expected session dates. Calendar-day count is not trading-session count. No weekend/holiday inference, timezone conversion, sorting, forward filling or compression of missing sessions is permitted. Exchange trading dates use the adapter's supplied date/timezone; timestamp-only bars retain an explicitly labelled UTC-date proxy rather than claim verified exchange-calendar conversion.

Invalid input/configuration is distinct from an unavailable calculation. A valid but short, stale or incompletely covered window must carry a typed unavailable reason and required/observed sample counts, not zero or an invented neutral value. Provenance and formula/parameter/unit metadata accompany the calculation, including identity, adjustment and source/retrieval timestamps. Returned volumes retain their feed scope; an IEX volume ratio is not consolidated relative volume.

IEX volume is labelled `partial`. Twelve Data `endOfDay` volume is labelled `completeButAccountCoverageUnverified`: documented historical full-exchange volume becomes available after midnight ET on the next trading day, but actual availability/depth still depends on instrument/account. This is not the partial real-time quote feed. Unsupported volume scope makes relative volume unavailable. Retrieval before the bar's source timestamp is invalid; there is no implicit freshness default, and each metric checks every retrieval in its own required window against the caller's maximum age.

Raw-price returns require explicit comparability confirmation so an unverified split cannot silently become an economic return. This slice cannot verify corporate actions or calibrate opportunity quality. Remaining MACD/ATR/volatility/liquidity calculations are separate increments; no scoring, orders, trade plans or win-rate claims are added.

### Explicit card presentation

`backend/lib/daily_indicator_service.dart` is shared by `GET /api/v1/market-data/indicators?symbol=...` and `get_technical_indicators`. The GET route accepts only one symbol parameter and preserves existing authentication, origin and display-permission gates. Its envelope is `{status, data, coverage, sources, limitations}`; success serializes engine output unchanged, while unavailable data returns null and no fabricated sources. Each action fetches raw history once, bounded to 120 calendar days/records, with lookback 20, trend lag 1, RSI period 14 and five-minute retrieval freshness. Analysis cutoff is captured after retrieval.

Expected sessions are independent of returned bars: a static regular US-equity calendar for 2025–2030 excludes weekends, normal NYSE holidays and the January 9, 2025 Carter closure. Conservative 06:00 UTC completion/availability proxies account for delayed EOD availability; this is not an authoritative exchange calendar or timezone conversion. Unsupported years fail explicitly; unknown exceptional closures appear as coverage gaps, not silently skipped sessions. Sources identify only actual validated completed-bar dates and retrieval times. The research prompt requires interpretation of exact returned values/units, not recalculation, forecasts, scoring or trade plans.

Each quote card's **Calculate daily indicators** action makes a single read-only request to the backend for that ticker; it does not invoke AI or fetch history on page load. `LocalMarketDataService.indicators` uses the same validated local/same-origin service boundary, disabled redirects and sanitized errors as the existing market client. `IndicatorSnapshot` validates known provider/feed, exact formula version/units, fixed periods, finite/ranged values, consistent availability/counts, timestamp/date provenance and matching provider source paths before presentation.

Cards show values and typed unavailable reasons separately, with sample counts, data cutoff, session date, provider/feed, coverage/volume scope, formula version and actual sources. Loading, concurrent actions and quota failures remain explicit. Refresh/backend/service changes clear previous snapshots and discard stale in-flight responses; there is no indicator polling or automatic retry. Model-generated explanations remain visibly separate from deterministic indicator output.

## Target architecture when later phases are approved by the checklist

```text
Flutter UI (dashboard, settings, idea details, journal)
    -> presentation state/view models (user intent, formatting, UI loading/error state)
    -> domain services (screening, portfolio sizing, prompt validation, outcome rules)
    -> repositories (market data, research, recommendations, journal, preferences)
    -> provider adapters (Schwab/approved free feed, SEC, authorized IR/news, OpenAI)
    -> local/self-hosted backend + append-only database (credentials, scheduling, quotas, history)
```

Build only the abstractions needed for the next phase. All quantitative logic (indicators, allocation, entry/stop/target constraints, fill simulation, metrics) belongs in deterministic application code, not GPT. Provider adapters normalize to internal records while retaining provider, source timestamp, retrieval timestamp, freshness/delay, adjusted/raw status, exchange/feed, and missing-data indicators.

## Provider and data flow

1. Configuration disables providers by default and records access/limits/status without exposing API secrets to UI.
2. A scheduled or explicit user action first checks quota/cache/deduplication; disabled or exhausted providers do not receive requests.
3. Provider-specific raw responses are validated, normalized, source-stamped, and stored only when the provider permits the intended retention/use. Social collection uses one optional Bright Data adapter/key for X and/or Reddit, not direct platform API clients; it remains disabled until terms authorize collection and subsequent model processing.
4. Deterministic screening rejects incomplete, stale, illiquid, unsupported, or unsafe candidates before any OpenAI call.
5. The UI shows exactly which timestamped evidence will be sent. Optional OpenAI analysis uses only verified research and structured output; output is schema-checked and numeric constraints are revalidated.
6. Every generated recommendation and no-trade decision is journaled before user save/ignore choice. New analysis is a new version, not an overwrite.
7. Outcome evaluation uses future observations only after the original plan is sealed and uses conservative execution assumptions.

## Security and privacy

- No third-party API credentials in Flutter Web, source control, mock data, or logs. A local secure store may protect personal desktop/mobile credentials only if its threat model is documented; a backend is needed for multi-user/shared automation.
- Never put OpenAI or Schwab secrets into app assets, build-time public defines, URL query parameters displayed in logs, or prompt previews. Redact headers/tokens and account identifiers in diagnostic output.
- Browser requests to providers with CORS restrictions are not a reason to expose a credential or proxy through an untrusted public endpoint. Use a local/self-hosted backend or disable the feature.
- OpenAI API data is not used for model training by default, but abuse-monitoring retention can be up to 30 days by default; Zero Data Retention requires eligibility/approval. Send minimal data and avoid personal account details.
- Provider retention/display/AI processing rights must be verified before storing market data or forwarding it to OpenAI. SEC/issuer public text still requires provenance and ordinary copyright/terms review.
- Live brokerage capability is out of scope through Phase 8. A later brokerage integration must enforce paper-only default, long-only/cash-only restriction, human confirmation, and no autonomous order lifecycle actions in backend logic.

## Persistence plan

Phase 1 is intentionally in-memory and resets on app restart. Phase 5+ preferences may begin with local storage, but recommendations/outcomes require durable append-only storage and backups. Prefer a local self-hosted service/database with migrations and export/restore over paid hosting. Retain references or normalized permitted facts rather than copying licensed data when terms do not allow storage. Exact database choice is deferred until journal schema and single-device/multi-user needs are established.

## Major decisions

- No third-party package added for Phase 1; the starter app has no state complexity justifying a framework.
